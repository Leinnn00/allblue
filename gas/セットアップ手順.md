# メール予約リクエスト セットアップ手順

所要時間: 10分ほど。Googleアカウントがあれば無料。

## 1. スプレッドシートを作る
1. https://sheets.google.com で新しいスプレッドシートを作成(名前は「All Blue 予約リクエスト」など)。

## 2. スクリプトを貼る
1. メニュー「拡張機能」→「Apps Script」を開く。
2. 最初からある `function myFunction() {}` を消し、`gas/Code.gs` の中身を全部貼る。
3. 先頭の `NOTIFY_EMAIL` に、通知を受け取るメールアドレスを書く(今は仮で個人のアドレスでOK)。
4. 保存(💾)。

## 3. ウェブアプリとして公開する
1. 右上「デプロイ」→「新しいデプロイ」。
2. 種類の歯車 → 「ウェブアプリ」。
3. 設定:
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
4. 「デプロイ」→ 権限の確認画面が出たら許可する
   (「このアプリは確認されていません」と出たら「詳細」→「(安全でないページ)に移動」→許可)。
5. 表示される **ウェブアプリのURL**(`https://script.google.com/macros/s/.../exec`)をコピー。

## 4. サイトにURLを設定する
`apply.html` の `MAIL_ENDPOINT = ""` の `""` の中に、コピーしたURLを貼る。
(このURLは公開されても問題ありません。メールアドレスはスクリプト側にだけ書かれています)

## 5. 動作確認
1. サイトの申込みページで日付を選び、フォームを送信。
2. スプレッドシートに「予約リクエスト」シートができて1行増え、通知メールと受付メールが届けばOK。

## 日別料金・満席・受付締切の使い方

`Code.gs` を更新して再デプロイしたあと、サイトの申込みページを1回開くと、スプレッドシートに次の2つのシートが自動で作られます。

### 「料金ルール」シート
| プラン | 開始日 | 終了日 | 大人料金(円) | 子供料金(円) | 状態 | メモ |
|---|---|---|---|---|---|---|
| (ドロップダウンで選ぶ) | 2026/12/24 | 2026/12/31 | 7500 | 5500 | | 年末料金 |
| 全プラン | 2026/11/10 | 2026/11/10 | | | 停止 | 臨時休業 |

- プランは「全プラン」か、ドロップダウンから個別に選ぶ。
- 料金が空欄なら通常料金(plans.js)を使う。終了日が空欄なら開始日の1日だけ。
- 状態が空欄なら「受付中」。「満席」「停止」にすると、その日はカレンダーで選べなくなる。
- 日付が重なる行は、**下の行が優先**される。
- 「全プラン」の行には料金を入れず、状態(休業など)だけに使うのがおすすめ。
- カレンダーには、設定した料金だけを表示する(通常料金との二重表示はしない)。

### 「受付設定」シート
| プラン | 何日前まで受付 | メモ |
|---|---|---|
| 全体 | 1 | 1 = 前日まで受付 |
| (ドロップダウンで選ぶ) | 2 | 早朝出発のため2日前まで |

- 「全体」が全プラン共通。プランを選んだ行は、そのプランだけ上書きする。

### 反映のタイミング
- 編集してから、サイトに反映されるまで最大1分ほどかかる。
- サイトの内容は、お客さんがページを開いたときに読み込まれる。

## あとで変更するとき
- **通知先メールアドレスの変更**: `NOTIFY_EMAIL` を書き換え → 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」→「デプロイ」。URLは変わらない。
- **コード(Code.gs)を変更したとき**も、同じ手順で新バージョンをデプロイする。

## 注意
- 1日に送れるメールの上限は、無料のGmailで約100通。通常の予約数なら十分。
- お客さんへの受付メールは、このスクリプトを動かすGoogleアカウント(Gmail)から送られる。本番では共用アドレスのアカウントで作ると、送信元が自然になる。

## 定員の自動停止(インストラクター数ベース)

オールブルーは「1ツアー=日本人インストラクター1人」。その日に**確定した**ツアーの種類が上限(初期値5)に達すると、
**その日は別のツアーが選べなくなる**(すでに確定しているツアーへの追加申込は引き続き可能)。

### 使い方
1. 予約が確定したら、シート「予約リクエスト」の **対応状況** を「確定」にする(ドロップダウン)。
2. LINEで入った予約は、シートの最後の行に手で足す: **希望日**(2026/11/05 など)、**ツアー**(E列・ドロップダウン)、**対応状況=確定** を入れる。
3. 上限の数字は、シート「受付設定」の「1日の最大ツアー種類数」の行(初期値5)で変更する。
4. 反映は最大1分遅れる。「キャンセル」にすれば枠は戻る。

### 反映するとき
- Code.gs を差し替えて **再デプロイ**(新しいバージョン)。
- 初回は、スクリプトのエディタで `ensureSheets_` を一度実行すると、「受付設定」に上限の行と、「予約リクエスト」のドロップダウンが作られる(実行しなくても、次のリクエストか設定取得のときに自動で作られる)。
- 「予約リクエスト」の E 列(ツアー)がドロップダウンになり、新しいリクエストには「ID｜名前」が入る(以前のJ列「プラン」は不要になったので削除される)。

## シート名・項目名が英語になりました

英語話者のスタッフも使えるように、シート名・1行目の見出し・状態の値を英語にした(ドロップダウンのプラン名は「ID｜日本語名」のまま)。

| 以前 | いま |
|---|---|
| 予約リクエスト | Booking Requests |
| 料金ルール | Price Rules |
| 受付設定 | Booking Settings |
| 対応状況: 未対応/対応中/確定/キャンセル | Status: New / In progress / Confirmed / Cancelled |
| 状態: 受付中/満席/停止 | Status: Open / Full / Closed |
| 全プラン / 全体 | All plans / Global (all plans) |
| 1日の最大ツアー種類数 | Max tour types per day |

Code.gs を再デプロイして `...exec?action=config` を開くと、既存のシート・見出し・値が自動で英語に置き換わる(行のデータは消えない)。
スタッフ・お客様宛のメールの文面は日本語のまま。

## LINE予約の自動記録（Messaging API webhook）

サイトの「この内容でLINEに送る」で届いた予約メッセージを、自動でシート（Booking Requests）に記録し、自動返信します。
Statusを Confirmed にすると、メールが無い行（LINE経由）にはLINEで確定連絡をpushします。

1. LINE公式アカウントマネージャー → 設定 → Messaging API → 「Messaging APIを利用する」（プロバイダー作成）
2. LINE Developers → 該当チャネル → Messaging API設定 → 「チャネルアクセストークン（長期）」を発行
3. Apps Script → プロジェクトの設定 → スクリプトプロパティに追加
   - `LINE_CHANNEL_ACCESS_TOKEN` = 手順2のトークン
   - `LINE_WEBHOOK_KEY` = 推測されにくい英数字の文字列（自分で決める）
4. Code.gs を貼り替え → デプロイを管理 → 新バージョンで再デプロイ（NOTIFY_EMAIL を再入力）
5. `…/exec?action=config` を開いて列を13列に移行、`runSetup` を実行（権限を再承認）
6. LINE Developers → Webhook URL = `…/exec?key=<LINE_WEBHOOK_KEY>`、「Webhookの利用」ON
   （Verifyは302でエラー表示になることがありますが、イベントは届きます）
7. LINE公式アカウントマネージャーの応答設定：Webhook ON。あいさつメッセージは使用可。自動応答メッセージはOFF推奨（二重返信防止）
8. テスト：スマホでサイトから申し込みメッセージを送信 → シートに行追加・自動返信・スタッフ通知メールを確認

注意
- push送信は月間メッセージ数にカウントされます（reply は無料）。
- トークン・キーは他人に見せない。
- 「Webからのご予約リクエスト」を含むテキストメッセージのみ記録します。
- 元に戻す場合：Code.before-linewebhook.gs / apply.before-linecode.html

### 未対応まとめメール（毎日18:00 フィリピン時間）
- LINE予約の1件ごとのスタッフ通知メールは廃止（Webフォーム予約の即時通知は従来通り残す）。毎日18:00に、Status が New の行があれば1通にまとめて通知します（0件なら送りません）。
- 時刻は Code.gs の `DIGEST_HOUR` で変更。変えたあとは、トリガー画面で sendDigest_ のトリガーを削除して `runSetup` を再実行してください。
- 再デプロイ後に `runSetup` を実行するとトリガーが登録されます（権限の再承認あり）。


## 日ごとの受付上限（Daily Capacity シート）
インストラクターが休む期間などに、「この日から2週間は3種類まで」のように上限を変えられます。
- シート「Daily Capacity」に1行ずつ書く：Start date / End date（空なら1日だけ）/ Max tour types per day / Notes
- 例：2026/12/01〜2026/12/14 を 3 → その期間は、確定済みが3種類に達した日から他のプランが満席表示になる
- 0 にすると、その期間は確定が無くても全プラン満席（受付停止）
- 期間が重なったら、下の行が優先。書かない日は「Booking Settings」の Max tour types per day（標準）が使われる
- 反映まで最大1分。初回は Code.gs を再デプロイし、runSetup（または ?action=config を開く）でシートが作られます

## Booking Requests の列の並び（新）
Status / Source / Received / Name / Tour / Desired date / Details / Request / notes / Email / Phone / LINE userId / Confirmation email / Policy agreed
- 毎日触る Status と、予約の経路 Source を左端に。左4列（〜Name）は固定表示。
- Status は色分け（New=黄、In progress=青、Confirmed=緑、Cancelled=灰）。
- 再デプロイ後に runSetup（または ?action=config）を実行すると、既存の行も自動で新しい並びに変換されます。
- 元に戻す場合は Code.before-columns.gs（ただし並び替え済みの列は自分で戻す必要があります）。
